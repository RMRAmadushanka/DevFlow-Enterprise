# 6. Folder Structure

This structure is designed to stay flat and predictable at 100+ pages.
Feature/business code (not part of this deliverable) is expected to live
under `src/features/*` or `src/app/(routes)/*` later — it should **never**
reach into `src/design-system` internals directly; it should only consume
`src/components/ui` and the documented token exports.

```
DevFlow Enterprise/
├── docs/
│   └── design-system/            # This documentation set
│
├── src/
│   ├── app/                      # Next.js App Router
│   │   ├── layout.tsx            # Root layout: fonts, ThemeProvider, AppProviders
│   │   ├── globals.css           # ★ Single source of truth for all design tokens
│   │   ├── page.tsx              # Redirects to /design-system (no app pages exist yet)
│   │   └── design-system/
│   │       └── page.tsx          # Living style guide / token showcase (dev-only)
│   │
│   ├── components/
│   │   └── ui/                   # shadcn/ui primitives + DevFlow additions
│   │       ├── button.tsx, input.tsx, select.tsx, dialog.tsx, …  (generated by shadcn)
│   │       ├── typography.tsx    # <Text> — semantic type-scale primitive (DevFlow addition)
│   │       └── container.tsx     # <Container> — grid/max-width primitive (DevFlow addition)
│   │
│   ├── design-system/            # Design-system-specific logic (not generic UI)
```

## Rationale for the split between `components/ui` and `design-system`

- **`components/ui/*`** — renderable primitives. Anything you'd drop into
  JSX (`<Button>`, `<Card>`, `<Text>`). This is the shadcn/ui convention;
  keeping it means the shadcn CLI (`npx shadcn add …`) keeps working for
  new primitives without any path juggling.
- **`design-system/*`** — the system *behind* the primitives: tokens as
  data (for non-JSX consumption), the theme provider/switcher, and the
  motion variant library. Nothing here renders visible UI directly (aside
  from `theme-toggle.tsx`, which is a thin composition of `components/ui`
  primitives).

## Where future work plugs in (not part of this deliverable)

| Future concern | Where it goes |
|---|---|
| Business components (e.g. `PipelineCard`, `IncidentTimeline`) | `src/features/<domain>/components/` |
| Pages / routes | `src/app/(product)/…` |
| API/data-fetching hooks | `src/features/<domain>/hooks/` (TanStack Query) |
| Domain Zustand stores | `src/features/<domain>/store.ts` |
| Zod schemas for forms | `src/features/<domain>/schemas.ts` |

Business code should import **from** `components/ui` and
`design-system/tokens`, never the other way around.
